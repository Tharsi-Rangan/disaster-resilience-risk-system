## 📌 Project Overview

The **Disaster Resilience Risk System** is a secure, RESTful full-stack application that helps contractors and administrators evaluate disaster risks (floods, earthquakes, extreme weather) before initiating infrastructure projects. 

### Key Features:
- **Real-time Data Monitoring**: Live integration with OpenWeather and USGS Earthquake APIs.
- **Intelligent Assessment**: Rule-based and AI-enhanced scoring system for infrastructure safety.
- **AI-Powered Mitigation**: Contextual recommendations generated by Google Gemini AI.
- **Interactive Kanban**: Task-based workflow for managing recommendation implementation.
- **Professional Reporting**: Executive PDF generation for site supervisors and stakeholders.

## 🧪 Testing Instruction Report (Evaluation 02)

To ensure high reliability, the system implements a triple-layer testing strategy.

### 1. Testing Environment Configuration
- **Database**: `mongodb-memory-server` used for isolated, database-less unit and integration testing.
- **Authentication**: JWT tokens are programmatically mocked or generated via `beforeAll` hooks.
- **Setup**: `backend/tests/setup.js` handles environment injection (`JWT_SECRET`, `MONGO_URI`).

### 2. How to Run Unit & Integration Tests
We used **Jest** and **Supertest** to verify 40+ critical paths.

```bash
cd backend
# Run all unit and integration tests
npm run test

# Run only Component 4 (Mitigation) tests
npm run test:unit
npm run test:integration
```

### 3. Performance Testing (Artillery)
Load testing was performed using **Artillery** to ensure the API handles concurrent user activity.
- **Simulated Load**: 10 users per second.
- **P95 Latency**: **376ms** under sustained load.
- **Success Rate**: 100% (Zero failures).

**Execution command**:
```bash
cd backend
npm run test:performance
```

## 📂 API Endpoint Documentation

### 🔐 Authentication (Shared)
| Method | Endpoint | Auth | Description |
| :--- | :--- | :--- | :--- |
| `POST` | `/api/auth/register` | No | Register new Contractor/Admin |
| `POST` | `/api/auth/login` | No | Login and receive JWT Token |
| `POST` | `/api/auth/verify-email` | No | Verify account via email OTP |

### 📁 Project Management (Comp 1)
| Method | Endpoint | Role | Description |
| :--- | :--- | :--- | :--- |
| `POST` | `/api/projects` | User | Create a new infrastructure project |
| `GET` | `/api/projects` | User | List projects owned by the user |
| `PATCH`| `/api/projects/:id/status` | Admin | Approve or reject a project status |

### 🌍 Risk Data & Snapshot (Comp 2)
| Method | Endpoint | Auth | Description |
| :--- | :--- | :--- | :--- |
| `POST` | `/api/risk-data/fetch/:pid` | Yes | Fetch live weather/earthquake snapshots |
| `GET` | `/api/risk-data/:pid/latest`| Yes | Get latest environmental snapshot |

### 📊 Assessment Engine (Comp 3)
| Method | Endpoint | Auth | Description |
| :--- | :--- | :--- | :--- |
| `POST` | `/api/assessments/run/:pid` | Yes | Execute risk scoring algorithm |
| `GET` | `/api/assessments/:pid/latest`| Yes | View results of latest assessment |

### 🛡️ Mitigation & Recovery (Comp 4)
| Method | Endpoint | Auth | Description |
| :--- | :--- | :--- | :--- |
| `POST` | `/api/mitigation/generate/:pid`| Yes | Generate AI Mitigation Recommendations |
| `PATCH`| `/api/mitigation/:id/recommendations/:rid` | Yes | Update task status (Boardroom/Kanban) |
| `DELETE`| `/api/mitigation/:id` | Admin | Remove historical mitigation plans |

## 🚀 Setup Instructions

### 1. Clone & Dependencies
```bash
git clone https://github.com/Tharsi-Rangan/disaster-resilience-risk-system.git
cd disaster-resilience-risk-system
npm install
```

### 2. Environment Configuration
Create a `.env` file in the `backend/` directory:
```env
PORT=5000
MONGO_URI=your_mongodb_atlas_uri
JWT_SECRET=your_jwt_secret
GEMINI_API_KEY=your_google_ai_key
OPENWEATHER_API_KEY=your_weather_key
```

### 3. Run Locally
```bash
# Terminal 1: Backend
cd backend
npm run dev

# Terminal 2: Frontend
cd frontend
npm run dev
```
